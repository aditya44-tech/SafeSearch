1 System Overview

SafeSignal collects workplace safety reports, uses AI to classify their risk level, auto-generates corrective tasks, and provides dashboards for safety officers to track and resolve hazards.

What happens when you click "Run AI analysis"

  1. Gemini classifies the report → risk level (high/medium/low), hazard category, one-sentence justification
  2. SLA deadline is calculated: high=24h, medium=72h, low=7 days
  3. Audit log entry is created: "report_analyzed"
  4. Site score is recalculated (high-risk reports cost 15 points each)
  5. Clustering groups this report with semantically similar ones via text similarity
  6. Task extraction (second Gemini call for medium/high): generates 1-3 corrective tasks with department assignment
  7. Tasks are auto-created in the database with correct department, priority, and due date
  8. If risk is high, a toast notification fires: "Alert sent to Safety Officer"

5 AI Analysis Pipeline

The most critical feature. When "Run AI analysis" is clicked on a report, this pipeline executes in sequence.

Step 1: Classification (Gemini call #1)

Prompt sent to Gemini:

You are a workplace safety analyst reviewing near-miss and unsafe-condition reports to detect early warning signs of a potential serious injury or fatality (SIF). Given the report below, respond with ONLY valid JSON: { "risk_level": "high" | "medium" | "low", "hazard_category": "<short category>", "justification": "<one sentence explaining why>" } Guidance: - "high" = credible path to serious injury or death if unaddressed - "medium" = real hazard but lower severity or already partially mitigated - "low" = minor/procedural issue unlikely to cause serious harm Report: Site: {{site}} Reporter role: {{reporterRole}} Report text: "{{reportText}}"

Config: temperature=0.1, maxOutputTokens=500, responseMimeType="application/json"

Fallback: If no Gemini API key or all 5 models fail → keyword-based classifier in fallbackAnalysis() scans report text for danger words (fall, unguarded, exposed wiring, confined space, etc.)

Step 2: Update Database

await prisma.safetyReport.update({ where: { id }, data: { riskLevel: analysis.risk_level, // "high" | "medium" | "low" hazardCategory: analysis.hazard_category, // "Fall Hazard" justification: analysis.justification, // "Unguarded scaffold..." status: "analyzed", // pending → analyzed analyzedAt: new Date(), slaDeadline, // calculated in step 3 }, });

Step 3: Side Effects (parallel)

SLA Calculation

function getSLADeadline(riskLevel) { if (riskLevel === "high") = now + 24h; if (riskLevel === "medium") = now + 72h; return now + 7 days; }

Site Score Recalculation

score = 100 - (high_count × 15) + speed_bonus speed_bonus = max(0, 30 - avg_resolution_hours / 2) clamped to [0, 100]

Step 4: Clustering

Compares the new report against all other analyzed reports using a two-stage process:

  1. Semantic hash — maps report text to a topic bucket (fall_heights, electrical, chemical, vehicle, equipment, confined_space, general) based on keyword detection
  2. Text similarity — Jaccard similarity on word tokens (words > 2 chars, lowercase, stripped of punctuation). Threshold: ≥ 0.25

If both match → same clusterId. Otherwise, new cluster created.

6 Auto-Task Generation

After classification, a second Gemini call extracts 1–3 corrective tasks for medium/high risk reports.

Task Extraction Prompt

You are a workplace safety operations manager. Given a safety report and its risk classification, extract specific corrective actions. Respond with ONLY valid JSON — an array of 1-3 tasks: [ { "title": "<short action verb phrase, max 80 chars>", "description": "<1-2 sentence explanation>", "priority": "urgent" | "high" | "normal" | "low" } ] Rules: - Each task must be a concrete, actionable step - Use action verbs: Install, Repair, Replace, Inspect, etc. - For high-risk: include immediate safety action AND root-cause fix - Keep titles under 80 characters

8 Clustering Algorithm

Groups semantically similar reports together so patterns like recurring hazards at a site become visible.

How it works

  1. Keyword hash: Map report text to one of 7 topic buckets: fall_heights, electrical, chemical, vehicle, equipment, confined_space, general
  2. Tokenize: Lowercase, strip punctuation, split on whitespace, filter words ≤ 2 chars
  3. Jaccard similarity: |intersection| / max(|A|, |B|)
  4. Threshold: ≥ 0.25 similarity AND same semantic hash → same cluster
  5. Cluster ID format: cluster_{hash}_{timestamp}
Example: Report A says "Scaffolding missing guardrails at 25 feet" and Report B says "Scaffold platform planks not secured at height". Both hash to fall_heights. Token intersection includes {scaffold, height, missing, guardrails, platform, planks, secured} → Jaccard ≈ 0.35 → clustered together.

9 Anomaly Detection

Detects sites where this week's report count or high-risk count suddenly spikes above the historical average.

Algorithm

  1. Get all reports from last 4 weeks
  2. Split into: this week vs. previous 3 weeks
  3. For each site, calculate:
    • thisWeekCount — reports this week
    • historicalAvg — total in previous 3 weeks / 3
    • thisWeekHigh — high-risk reports this week
    • historicalHighAvg — high-risk in previous 3 weeks / 3
  4. Anomaly if: thisWeekCount ≥ max(historicalAvg × 2, 3) OR thisWeekHigh ≥ max(historicalHighAvg × 2, 2)

The minimum thresholds (3 total, 2 high-risk) prevent false positives when historical data is sparse.

10 Natural Language Query

Users type questions in plain English. Gemini answers using only the report data.

How it works

  1. Fetch up to 200 reports from database
  2. Serialize as JSON: {site, date, risk, category, status, role}
  3. Send to Gemini with system prompt: "Answer using ONLY the data provided"
  4. Display answer as plain text

Fallback: If no Gemini key → keyword-based answers (e.g., "electrical" → count electrical hazard reports, "high risk" → count unresolved high-risk reports)

Example queries

  • "Which sites had electrical hazards this month?"
  • "How many high-risk reports are still unresolved?"
  • "What are the most common hazard categories at Metro Industrial Park?"

11 Photo Cross-Check

Upload a photo with a report → Gemini Vision checks if the image matches the described hazard.

Flow

  1. User selects a photo file on the report detail page
  2. File is converted to base64
  3. Sent to Gemini with text prompt + inline image data
  4. Gemini responds: {consistent: true/false, note: "..."}
  5. Result displayed as green (consistent) or red (inconsistent) banner
  6. Audit log entry created: "photo_crosschecked"

Technical detail: Uses gemini-3.6-flash directly (not the fallback chain) because it requires vision/multimodal support. The inlineData field carries the base64-encoded image with its MIME type.

12 SLA & Scoring

SLA Deadlines

Risk LevelDeadline
HIGH24 hours from analysis
MEDIUM72 hours from analysis
LOW7 days from analysis

Reports past their SLA show "OVERDUE" in red. The /alerts page filters for high-risk reports overdue by 48+ hours.

Site Score Formula

score = 100 - (highRiskCount × 15) + speedBonus speedBonus = max(0, 30 - avgResolutionHours / 2) score = clamp(score, 0, 100)

Every high-risk report costs 15 points. Faster resolution earns bonus points (max 30). The score is recalculated after every status change or risk override.

Task Lifecycle

  1. Auto-generation: When a medium/high report is analyzed, Gemini extracts 1-3 tasks → auto-created in DB with department, priority, due date
  2. Manual creation: Admin clicks "+ Assign" on a report → fills in title, details, picks department and priority
  3. Start work: Department clicks "Start work" → status changes to in_progress
  4. Mark done: Click "Mark done" → status changes to done
  5. Auto-resolve: When ALL tasks for a report are done AND the report status is acknowledged, the report is automatically set to resolved

Department Filter

Click any department button on the task board to filter tasks by that department. Tasks show the department icon + name, linked report site, hazard category, and due date.

14 PDF Export

The "Export PDF" button on the dashboard generates a downloadable HTML file that browsers can print to PDF.

Contents

  • Summary stats: Total reports, High risk count, Unresolved high-risk, Pending action
  • Unresolved high-risk table: Site, Category, Reporter, Date, Status, Justification
  • Top 5 riskiest sites: Site name, Total/High/Medium/Low counts
  • Risk breakdown: Percentage distribution across risk levels

Technical: The API route returns raw HTML with Content-Disposition: attachment. The browser renders it and users can print to PDF. No server-side PDF library needed.
